Hosting on Raspberry Pi 5 with Cloudflare Tunnel

A complete, battle-tested guide to self-hosting your website on a Raspberry Pi 5 using Cloudflare Tunnel — no open ports, no Dynamic DNS, and no headaches (god knows I had a few).

September 7, 2026   |   Raspberry Pi, Cloudflare, Self-Hosting

Introduction

After moving my site from GitHub Pages to a Raspberry Pi 5, I wanted a secure, always‑on solution that didn't require opening router ports or messing around with Dynamic DNS. Especially if I ever change WiFi providers or get a new router. Cloudflare Tunnel was the perfect answer, but getting it working wasn't entirely smooth.

This guide documents every step I took, including the three major fixes that turned a failing tunnel into a civil engineers dream. If you're setting up Cloudflare Tunnel on a Pi (or any home server), this will save you time debugging.

Project Goal: Host geosmin.ca (previously on GitHub Pages) on a Raspberry Pi 5 using Cloudflare Tunnel, allowing visitors to access it securely without opening ports or dealing with Dynamic DNS.

Installing cloudflared

I installed cloudflared using Cloudflare's official APT repository to ensure automatic updates.

# Add Cloudflare's GPG key
sudo mkdir -p --mode=0755 /usr/share/keyrings
curl -fsSL https://pkg.cloudflare.com/cloudflare-main.gpg | sudo tee /usr/share/keyrings/cloudflare-main.gpg >/dev/null

# Add the repository
echo 'deb [signed-by=/usr/share/keyrings/cloudflare-main.gpg] https://pkg.cloudflare.com/cloudflared any main' | sudo tee /etc/apt/sources.list.d/cloudflared.list

# Install
sudo apt-get update && sudo apt-get install cloudflared

Verify with cloudflared --version (expected: cloudflared version 2026.8.3 or similar).

Authentication with Cloudflare

Run the login command to authenticate your Pi with your Cloudflare account, this more or less shakes hands and confirms it is authenticated:

cloudflared tunnel login

This opens a URL in your browser; after logging in, Cloudflare saves a certificate at ~/.cloudflared/cert.pem.

✅ You have successfully logged in.
Credentials saved to: /home/geosminserver/.cloudflared/cert.pem

Creating the Tunnel

I attempted to create a tunnel named geosmin-rp5-server:

cloudflared tunnel create geosmin-rp5-server

Error: tunnel with name already exists

Since the name was taken, I used the existing tunnel ID 0b28e502-(tunnnel-id). Look, this exisiting tunnel was not here on its own. I made it with the Cloudflare dashboard, I didn't create it manually. But this causes me to go in a few circles because I can't seem to create a new tunnel with the same name (I did not realize the one made on the dashboard was actually created...).

Extract the token from the credentials file:

ls -la ~/.cloudflared/*.json
TOKEN=$(grep -o '"tunnel_token":"[^"]*"' ~/.cloudflared/0b28e502-(tunnnel-id).json | cut -d'"' -f4)
echo $TOKEN

Save the token securely:

sudo mkdir -p /etc/cloudflared
echo $TOKEN | sudo tee /etc/cloudflared/token
sudo chmod 600 /etc/cloudflared/token

Testing the Tunnel Manually

Initial test failed. I added the critical flags:

sudo cloudflared --edge-ip-version 4 --protocol http2 tunnel run --token YOUR_TOKEN
✅ Success indicators:
• INF Tunnel connection established
• Error 1033 when visiting the site, this is good! It means the tunnel works but no web server is running. If nginx is not setup or something of that nature this is to be expected.

Fixing Network Issues

Three problems were identified and solved:

ProblemCauseSolution
IPv6 Connectivity Failure Network doesn't support IPv6 --edge-ip-version 4
DNS Resolution Failure Router DNS slow/unreliable Set nameserver 1.1.1.1 and 8.8.8.8 in /etc/resolv.conf
UDP Port 7844 Blocked ISP/router blocks QUIC (UDP) --protocol http2 (uses TCP port 443)

The first solution forces the tunnel to use IPv4 instead of IPv6, again I wanted to avoid messing around with my router. If it came with IPv4 only out of the box that is what I am going with to start.

The second solution uses public DNS servers (Cloudflare and Google) instead of relying on the router's DNS, which may not always work great. This ensures that the tunnel can resolve domain names quickly and consistently.

The third solution switches the tunnel to use HTTP/2 over TCP port 443 instead of QUIC over UDP port 7844, which may be blocked by some ISPs or routers. This ensures that the tunnel can establish a connection even if UDP is blocked.

Permanent DNS fix (via NetworkManager):

# For WiFi
WIFI_NAME=$(nmcli -t -f NAME,TYPE con show --active | grep wifi | cut -d: -f1)
sudo nmcli con mod "$WIFI_NAME" ipv4.dns "1.1.1.1 8.8.8.8"
sudo nmcli con mod "$WIFI_NAME" ipv4.ignore-auto-dns yes
sudo nmcli con down "$WIFI_NAME" && sudo nmcli con up "$WIFI_NAME"

Final Working Command

sudo cloudflared --edge-ip-version 4 --protocol http2 tunnel run --token-file /etc/cloudflared/token

This command forces IPv4, uses HTTP/2 (bypassing UDP blocks), and authenticates with the saved token.

Post-Tunnel: Fixing 502 Bad Gateway

After the tunnel was healthy, visiting https://www.geosmin.ca returned a 502 Bad Gateway error.

Cause: The tunnel was routing to https://localhost:8080, but Nginx was serving plain HTTP.

Fix: In Cloudflare Dashboard → Zero Trust → Networking → Tunnels → edit the public hostname, change the service from https://localhost:8080 to http://localhost:8080.

Why this works: Cloudflare handles HTTPS for visitors; the tunnel talks to your Pi over HTTP locally, which is secure because the tunnel itself is encrypted.

Adding the Root Domain (geosmin.ca)

https://www.geosmin.ca worked, but https://geosmin.ca (without www) did not.

Fix: Add a new public hostname with the subdomain field blank and domain geosmin.ca, pointing to http://localhost:8080.

Now both geosmin.ca and www.geosmin.ca work.

Understanding DNS Records

Since nameservers at the registrar (WHC) now point to Cloudflare, all DNS records must be managed in Cloudflare Dashboard → DNS → Records.

You don't add tunnel records manually in DNS. Instead, adding a public hostname in the tunnel dashboard automatically creates the necessary CNAME records pointing to your tunnel's <UUID>.cfargotunnel.com address.

If you have other records (email MX, SPF, subdomains), copy them from your registrar's DNS editor and recreate them in Cloudflare. As this bad boy is now head honcho of the DNS.

Security Considerations

A huge question you should be asking is whether this is secure and safe. Again, just saying "internet man" told you to do it and hoping a foreign national isn't spying on you through your smart fridge is not wise. Don't worry here are some quick reasons why it is safe.

  • Encryption: Cloudflare handles HTTPS for visitors; the tunnel is encrypted.
  • Open Ports: No open ports on your router — the tunnel uses outbound connections.
  • File Access: Nginx only serves files in /var/www/geosmin/. Directory listing is disabled.
  • SSL: Cloudflare provides free SSL certificates.

Optional hardening for Nginx:

# Block hidden files
location ~ /\. { deny all; }

# Block sensitive file types
location ~* \.(env|log|sql|sqlite|json|yml|yaml|toml|ini|conf)$ { deny all; }

Now you can rest easy knowing that your tunnel is secure, your Nginx server is only serving the intended files, and your DNS is properly managed through Cloudflare. There may be other backdoors that are beyond my current scope but if they want your Raspberry Pi 5 that badly you probably have bigger problems than a website. The main takeaway is that this setup is secure for the average user and should be sufficient for hosting a personal website.

Key Takeaways

  • IPv6 isn't always available — forcing IPv4 is a common and necessary fix for many home networks.
  • DNS matters — public DNS (1.1.1.1) is more reliable than router DNS.
  • Protocol choice matters — HTTP/2 works where QUIC is blocked.
  • Error 1033 is good — it means the tunnel works, you just need a web server.
  • Token authentication — using the token directly (rather than a config file) is a simpler approach that works well.
  • Tunnel service must use HTTP locally — http://localhost:8080, not HTTPS.
  • Add routes for both www and root domains separately.
  • DNS is now managed in Cloudflare, not your registrar.

What's Next?

Once your tunnel is stable, you can:

  1. Install Nginx: sudo apt install nginx -y
  2. Configure Nginx to serve your site (update /etc/nginx/sites-available/default).
  3. Clone your GitHub Pages repository: git clone https://github.com/your-username/your-repo.git /var/www/your-site
  4. Set up auto-deployment (GitHub Actions or webhook).
  5. Add monitoring (e.g., uptime checks).
